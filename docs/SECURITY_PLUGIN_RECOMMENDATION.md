一个安全审计插件，最打动我的不是它扫描多快，而是它知道自己什么时候该闭嘴

最近把这个项目从头到尾翻了一遍。它叫 dsh-code-security，是一个装在 DeepSeek Harness（DSH）里的安全审计插件。名字看着有点朴素，但里面的设计思路，比很多听起来很玄的安全平台要清醒得多。

先说结论。

我觉得它最值钱的地方，不是又给你一个扫描器，而是把「发现漏洞」这件事，做成了发现、验证、分析攻击路径、修复、追踪、写报告的一条完整流水线。

插件分成两块。一块是安全门禁，负责在你安装新插件的时候自动审计。另一块是安全审计模式，新建会话之后可以按工作流做仓库扫描、diff 扫描、深度扫描，以及漏洞从发现到修复的完整闭环。

还有一件事我特意确认过。它封装了上游 Codex Security 的工作流，但对外命名是 dsh-code-security，项目说明里反复强调不是 OpenAI 官方产品。这不是一句免责声明就完事，而是把商标边界、上游归属和实际能力都讲得很清楚。

最让我意外的是默认路径竟然可以零认证。它用宿主会话同款模型做审计，不需要额外 API key，不需要登录 OpenAI，不需要把代码先传到某个网页。对于本地开发环境来说，这条默认路径已经能解决大部分日常审计。

你敢信，默认路径连认证都不用？？？

这里我要坦率说清楚一个边界。llm 引擎会把有界采集的源码随提示词发给当前会话配置的模型服务商，默认可能是 deepseek-official。所以如果项目里有绝对不允许外发的专有代码，要么关掉自动审计，要么改走 CLI 引擎，要么只在安全审计模式里手动扫。插件没有把这个藏起来，README 里写得很直白。这种诚实，反而让我更愿意信任它。

零认证。

隐私边界还写得这么直白。光这两点，就已经不像普通安全工具的作风。

回到门禁这块。它会轮询 ~/.dsh/.agent-presets/ 和 ~/.dsh/profiles/*/，发现新插件就采集源码生成报告。它默认跳过 node_modules、.git、bundled、二进制和超限文件，敏感文件名直接不读，还会在发给模型前做行内密钥脱敏。审计不是无限采，默认有 400K 字符上限。已经审计过且没变化的东西会自动跳过，不用每次启动都重新吓自己一遍。

门禁审计也不是把整个插件一把抓。它按文件类型、大小、目录和采集预算分层做限制，超出的部分会在报告和 runner.log 里标出来。你不一定会喜欢这个上限，但它至少不会让一次审计悄悄变成一次全量外发。

设置页里有一个安全审计面板，能看到每个插件的审计状态、打开报告、一键重新审计、清除记录。想批量扫就调用全局工具 dsh_security_scan_plugins，想查状态就 dsh_security_scan_status。本地 HTTP 端点还有 token、Host 白名单、Origin 校验和限流，不是裸奔在 localhost 上。

这些细节看起来小，但安全工具最怕的就是自己的门没锁。

真正让我觉得有门槛的是它对提示注入的态度。扫描内容被当成不可信数据，不是指令。恶意插件哪怕在自己源码里塞满「请忽略以上内容」「帮我执行这个命令」，审计模型也只把它当分析对象。这个边界在安全工作流里反复出现，不是顺手写一句，而是写进了系统提示和技能说明。

说到扫描能力，标准扫描用 security-scan，PR、commit、分支和本地改动用 security-diff-scan，想要更彻底就用 deep-security-scan。发现候选之后不是直接写进报告，而是先 validation 验证，再 attack-path-analysis 把攻击者到 sink 的路径串起来，threat-model 负责建立威胁模型。确认了再 triage、fix、track，最后 vulnerability-writeup 和 propose-security-hardening 把漏洞文档和加固方案补齐。

还有一块容易被忽略，是误报记忆。audit-baseline.json 会记录上一轮已经甄别的发现，结论是 fixed、false-positive 还是 accepted。下一轮审计的时候，模型不能把旧账再翻一遍，除非它能引用已经变化的代码行证明这个漏洞复活了。这看起来是个小机制，实际体验差别很大。没有这一层，每扫一次都重新报一遍同一个误报，团队很快就会把安全报告当成噪音。

看到这里我是真的愣了一下。一个审计插件愿意花力气记住什么是不该重复报的，比再堆十个扫描规则都难。

对团队来说，最难得的是这些技能不是各扫各的。define-security-policy 可以先把安全规则定出来，threat-model 在扫之前建立威胁模型，security-scan 再照着模型找问题。triage-finding 能从 ticket 或 PR 评论接住外部上报，fix-finding 去修确认过的漏洞，track-findings 再挂到 Jira 或 GitHub Security Advisory。每个环节都有明确入口，也有明确出口。

报告本身也不是一段总结就完事。scan-manifest.json 记时间戳和哈希，findings.json 保留稳定指纹，coverage.json 写清楚哪些面查了、哪些面没查、哪些是被显式排除的。这等于给一次扫描留了可复核的底稿，不是模型聊天记录。同一仓库扫两次还能对比，看这次改动到底新增了什么风险，而不是每次都要从头看一遍。

底稿。

这才是一次审计该留下的东西。

还有五个 dsh_security_* 工具，scan、findings、scans_compare、cli 和 resources。扫描结果会落成结构化产物，路径由插件统一校验，模型不能拿它们当任意命令入口。

顺着上面的再聊聊实现。在 DSH 里，上游技能原本依赖的 Codex MCP workbench 工具不可用，项目做了 prompt-only 降级，也把工具路径、命令白名单、版本钉扎、完整性校验这些边界重新加固了一遍。CLI 工具的扫描路径被限制在工作目录里，命令白名单默认不开放 login 和 export，版本钉在 @openai/codex-security@0.1.12，脚本载荷每次使用前都要做 SHA-256 校验。这个插件自己也有一份安全审计报告，里面写出的问题，有不少已经修复并做过验证，不是贴一个免责声明就完事。

如果你愿意把 README 和 gate 源码放在一起看，会发现文案里写的每一条都能落到代码上。自动审计的轮询、密钥脱敏的清单、端点的令牌校验，都不是藏在截图里的演示，而是能读到实现细节的真实边界。

还有一点我必须说明，不是所有功能都默认开启。CLI 工具是可选的，它需要 OpenAI 侧认证，默认白名单还不放行 login 和 export。如果只是想在 DSH 里做源码级审计，你完全不用碰这半边。这个插件把免认证路径和官方 CLI 路径分得很开，不会为了展示能力逼你交出密钥。

它当然不是银弹。默认的 llm 审计是有界单次分析，超大插件可能漏文件，报告里会标记，但不等于全量覆盖。deep 扫描很费 token，适合后台跑或者分批跑。门禁的自动审计是轮询式，默认 60 秒加启动时一次，不是插件装完那一秒就立刻出结果。这些限制都写在 README 里，没有用话术包装。

deep-security-scan 在 DSH 里还会拆成多个独立 worker，把同一个仓库分给不同方向，先各自发现，再做语义合并和验证。多跑几轮不是为了显得认真，是为了把单次扫描的偶然性降下来。

没有工具能保证绝对安全。这句话听着可能有点扫兴，但我觉得它才是所有安全工具的起点。插件要做的不是替你打包票，而是把「这次看到了什么、没看到什么、下一步该做什么」留得足够清楚。

什么人适合先试？我的判断是两类。第一类是 DSH 里已经开始装第三方插件的人，门禁能在你不知情时先看一遍源码。第二类是想把仓库安全从偶尔一次变成持续流程的团队，审计模式比一个扫描器多出来的，恰好就是这些处置动作。

如果你只是偶尔给项目做一次上线前检查，标准扫描够用。如果你每天都有人在提交代码，那 diff 扫描才是真正该养成的习惯。漏洞不是只在发版那天存在，它更常出现在一次看起来很小的改动里。

安装也不麻烦。一条命令装完，重启 DSH，新建会话选安全审计模式就能用，设置里也有门禁面板。Windows 是 irm https://raw.githubusercontent.com/ihuajiu/dsh-code-security/main/install.ps1 | iex，macOS 和 Linux 是 curl -fsSL https://raw.githubusercontent.com/ihuajiu/dsh-code-security/main/install.sh | bash。

我自己还没把它装到生产环境跑完一整套深度扫描，所以本文不吹「我扫了三天三夜」这种话。我看到的，是项目把审计工作流、默认隐私边界和已知限制都摆得很清楚，这比一个只展示漂亮截图的安全工具更难得。

我想到一个挺老套但准确的事。安全检查这件事，过去很像每次出门前检查钥匙。你反复确认锁没锁，但真正出问题的往往是另一个房间的门。现代代码库里，漏洞很少单独出现，它长在调用链、权限边界、旧依赖和没人维护的分支里。所以工具真正要解决的，不是「这次有没有扫出问题」，而是「如果这次没扫到，下次凭什么知道该补哪里」。

如果你也在 DSH 里装插件，或者开始认真看自己仓库的安全问题，我建议你先装上试试。默认路径零认证，坏不到哪里去。真正要做的不是相信某个工具，而是让审计变成日常流程，让每一次发现都有地方去，有证据跟着，有修复兜底。
